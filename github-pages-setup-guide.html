研究室Webサイト：GitHub側の設定手順

Academic Pages（Jekyll）をGitHub Pagesで無料公開するための、Organization作成から公開確認までの手順です。

推奨構成： 研究室用のGitHub Organizationを作成し、その配下に公開リポジトリ <Organization名>.github.io を置きます。個人アカウントへの依存を避けられ、将来の引き継ぎが容易です。

1. GitHub Organizationを作成する

  1. GitHub右上のプロフィール画像から Settings を開きます。
  2. Organizations → New organization と進みます。
  3. 無料プランの GitHub Free を選択します。
  4. Organization名と連絡先メールアドレスを設定します。

例えばOrganization名を future-coexistence-lab とすると、公開URLは次のようになります。

https://future-coexistence-lab.github.io/

Organization名はURLに含まれるため、短く分かりやすい英小文字の名称が適しています。

GitHub公式：Organizationを新規作成する

2. 管理者とメンバーを設定する

管理継続性を確保するため、可能であればOwnerを2名登録します。

対象者推奨権限用途
主担当教員OwnerOrganization全体とサイトの管理
引き継ぎ担当の教員・職員Owner不在時や異動時の管理継続
更新を担当する学生Write記事や業績情報の編集
閲覧のみのメンバー原則不要公開サイトは誰でも閲覧可能

メンバーの追加は Organization → People → Invite member から行います。各Ownerは二要素認証を有効にしておくことを推奨します。

GitHub公式：Organizationの所有権の継続性を維持する

3. GitHub Pagesの公開を許可する

Organizationの設定で、公開GitHub Pagesサイトを作成できることを確認します。

Organization
└─ Settings
   └─ Member privileges
      └─ Pages creation → Publicを許可

GitHub公式：OrganizationのGitHub Pages公開を管理する

4. 公開リポジトリを作成する

Organizationの画面から New repository を選び、次のように設定します。

項目設定例
Ownerfuture-coexistence-lab
Repository namefuture-coexistence-lab.github.io
VisibilityPublic
Add a README fileチェックしない
Add .gitignoreNone
LicenseNone、または後から設定
既にローカルにサイト一式があるため、GitHub側ではREADMEなどを初期作成しません。空のリポジトリにすることで、最初のpush時の競合を避けられます。

Organizationサイトにする場合、リポジトリ名は必ず次の形式にします。

<Organization名>.github.io

GitHub公式：GitHub Pagesとは

5. ローカルのJekyll設定を変更する

リポジトリを作成したら、ローカルサイトの _config.yml を実際のOrganization名に合わせます。

url: "https://future-coexistence-lab.github.io"
baseurl: ""
repository: "future-coexistence-lab/future-coexistence-lab.github.io"

OrganizationサイトをルートURLで公開するため、baseurl は空欄のままにします。

6. GitHubへ初回アップロードする

ターミナルで次のコマンドを実行します。Organization名は実際に取得した名称へ置き換えてください。

cd /Users/t.oshima-hino/Repos/OK_lab_HP

git init -b main
git add .
git commit -m "Initial laboratory website"

git remote add origin https://github.com/future-coexistence-lab/future-coexistence-lab.github.io.git
git push -u origin main
GitHubへの認証を求められた場合は、ブラウザ認証、GitHub CLI、またはPersonal Access Tokenを使用します。GitHubアカウントの通常のパスワードではpushできません。

7. GitHub Pagesを有効化する

アップロード後、対象リポジトリで次の画面を開きます。

Repository
└─ Settings
   └─ Pages
      └─ Build and deployment
項目設定
SourceDeploy from a branch
Branchmain
Folder/(root)
Custom domain空欄
Enforce HTTPS有効

設定後、Save を押します。今回のサンプルはJekyllファイルをリポジトリ直下に置いているため、公開フォルダは /(root) です。

GitHub公式：GitHub Pagesサイトの公開元を設定する

8. 公開結果を確認する

  1. リポジトリ上部の Actions を開きます。
  2. pages build and deployment が緑色のチェックになるまで待ちます。
  3. https://<Organization名>.github.io/ にアクセスします。

公開や更新の反映には数分かかる場合があります。失敗した場合は、Actionsの失敗した処理を開いてエラーログを確認します。

代表的なエラー原因

  • _config.yml のインデントや記号の誤り
  • Markdown先頭のfront matterの記述不備
  • 画像パスやファイル名の大文字・小文字の不一致
  • Jekyllテーマまたはプラグインの設定不整合

9. 運用開始後の権限と保護設定

初期段階は主担当教員が main ブランチへ直接pushする運用で構いません。複数人で更新する段階になったら、次の設定を検討します。

Repository → Settings → Rules → Rulesets
  • main ブランチの削除を禁止
  • force pushを禁止
  • Pull Request経由の変更を必須化
  • 必要に応じて1名以上の承認を必須化

Pull Request必須化は更新手順が増えるため、Git操作に慣れてから導入するのが現実的です。

10. 公開情報の注意点

GitHub Pages用の公開リポジトリでは、HTMLやMarkdownだけでなく、画像や設定ファイルも原則として誰でも閲覧できます。

次の情報はリポジトリへ登録しないでください。

  • 非公開の学生名簿や個人の電話番号
  • 私用メールアドレス
  • Zoom、オンライン授業、LMSの限定URL
  • 未公開論文や査読中の原稿
  • APIキー、アクセストークン、パスワード
  • 掲載許可を得ていない顔写真

設定完了チェックリスト

  • 研究室用Organizationを作成した
  • Ownerを可能なら2名設定した
  • 公開Pagesサイトの作成が許可されている
  • <Organization名>.github.io という公開リポジトリを作成した
  • _config.yml のURLとリポジトリ名を変更した
  • ローカルのファイルを main ブランチへpushした
  • Pagesの公開元を main / (root) に設定した
  • Actionsのデプロイが成功した
  • 公開URLをブラウザで確認した
  • Ownerの二要素認証を有効にした
