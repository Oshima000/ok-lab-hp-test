動作確認用：個人リポジトリでのGitHub Pages設定

研究室用Organizationへ移す前に、個人のGitHubアカウントでAcademic Pagesを公開して動作確認する手順です。

推奨：個人アカウント内に ok-lab-hp-test のような通常名の公開リポジトリを作り、プロジェクトサイトとして確認します。個人のトップページ用リポジトリを消費せず、本番用Organizationサイトとも分離できます。

1. 2つの公開方式を確認する

方式 リポジトリ名 公開URL 用途
プロジェクトサイト（推奨） ok-lab-hp-test https://USERNAME.github.io/ok-lab-hp-test/ 今回の動作確認
個人ユーザーサイト USERNAME.github.io https://USERNAME.github.io/ 個人の代表サイト

個人ユーザーサイトは1アカウントにつき1つです。すでに USERNAME.github.io を使っている場合は上書きせず、プロジェクトサイト方式を選びます。

GitHub公式：GitHub Pagesサイトの種類

2. 事前に確認すること

  • GitHubアカウントのメールアドレスが確認済みである
  • 二要素認証を有効にしている
  • 既存の USERNAME.github.io リポジトリの有無を確認した
  • 公開してよい画像・文章だけがサイト内にある
完全無料のGitHub Freeで試す場合は、Pages用リポジトリをPublicにします。ソースコード、Markdown、画像、設定ファイルも公開情報になるため、個人情報や秘密情報を含めないでください。

GitHub公式：GitHub Pagesの利用条件と制限

3. 個人アカウントにテスト用リポジトリを作る

  1. GitHub右上の ＋ → New repository を開きます。
  2. Owner に自分の個人アカウントを選択します。
  3. Repository name を ok-lab-hp-test などにします。
  4. Visibility は Public を選択します。
  5. README、.gitignore、Licenseは追加せず、空のリポジトリを作ります。
項目設定例
OwnerUSERNAME
Repository nameok-lab-hp-test
DescriptionLaboratory website test
VisibilityPublic
Initialize this repositoryすべて未選択
既にローカルにAcademic Pages一式があるため、GitHub側ではREADMEを作らない方が、最初のpush時の履歴競合を避けやすくなります。

4. テスト公開用に _config.yml を設定する

USERNAME を実際のGitHubユーザー名へ置き換えます。プロジェクトサイトでは、URLにリポジトリ名が付くため baseurl の設定が重要です。

url: "https://USERNAME.github.io"
baseurl: "/ok-lab-hp-test"
repository: "USERNAME/ok-lab-hp-test"

プロフィール欄のGitHubリンクも、必要に応じて変更します。

author:
  github: "USERNAME"
baseurl の先頭には / を付け、末尾には付けません。ここが空欄のままだと、CSSや画像へのリンクがルート基準になり、表示が崩れることがあります。

5. ローカルからGitHubへpushする

このフォルダを初めてGit管理する場合は、次を実行します。

cd /Users/t.oshima-hino/Repos/OK_lab_HP

git init -b main
git add .
git commit -m "Initial test deployment"

git remote add origin https://github.com/USERNAME/ok-lab-hp-test.git
git push -u origin main

すでにGit管理され、別の origin が登録されている場合は、既存の接続先を不用意に変更せず、テスト用の接続先を別名で追加できます。

git remote add test https://github.com/USERNAME/ok-lab-hp-test.git
git push -u test main
認証を求められた場合は、ブラウザ認証、GitHub CLI、SSH、またはPersonal Access Tokenを使います。GitHubアカウントの通常のパスワードではpushできません。

6. GitHub Pagesを有効にする

GitHub上でテスト用リポジトリを開き、次の順に進みます。

Repository
└─ Settings
   └─ Pages
      └─ Build and deployment
項目設定
SourceDeploy from a branch
Branchmain
Folder/(root)
Custom domain空欄
Enforce HTTPS有効

Save を押すと、GitHub Pagesのビルドが開始されます。

GitHub公式：公開元を設定する

7. 公開結果を確認する

  1. リポジトリの Actions タブを開きます。
  2. pages build and deployment が緑色になるまで待ちます。
  3. https://USERNAME.github.io/ok-lab-hp-test/ を開きます。
  4. トップページ、Teaching、業績、メンバー、画像、ナビゲーションを確認します。

特に確認する箇所

  • CSSが適用され、レイアウトが崩れていない
  • プロフィール画像とページ内画像が表示される
  • 各メニューから正しいページへ移動できる
  • Teachingの現在・過去の科目が表示される
  • スマートフォン幅でも閲覧できる
  • 公開してはいけない情報が含まれていない

変更をpushしてから反映まで最大10分程度かかる場合があります。

GitHub公式：GitHub Pagesクイックスタート

8. よくある問題

症状確認箇所
404になるPagesのBranchが main、Folderが /(root) か確認
文字だけ表示されるbaseurl: "/ok-lab-hp-test" を確認
画像だけ表示されない画像パスとファイル名の大文字・小文字を確認
ビルドに失敗するActionsのログと _config.yml のYAML構文を確認
変更が見えないActions完了後にブラウザを再読み込みし、キャッシュも確認

GitHub公式：404エラーのトラブルシューティング

9. 本番用Organizationへ移行する

動作確認が完了したら、本番用Organizationの <Organization名>.github.io リポジトリへ同じサイトをpushします。その前に _config.yml を本番用へ戻します。

url: "https://ORGANIZATION.github.io"
baseurl: ""
repository: "ORGANIZATION/ORGANIZATION.github.io"

本番用接続先を追加してpushする例です。

git remote add production https://github.com/ORGANIZATION/ORGANIZATION.github.io.git
git push -u production main
個人のテストサイトを残す場合、本番公開後に両方が検索結果へ出る可能性があります。検証が終わったら、テストリポジトリの Settings → Pages で公開を停止するか、リポジトリを削除することを検討してください。

最終チェックリスト

  • 個人アカウントに公開テスト用リポジトリを作った
  • 既存の個人ユーザーサイトと競合していない
  • url、baseurl、repository をテスト用に設定した
  • main ブランチへpushした
  • Pagesを main / (root) から公開した
  • Actionsのデプロイが成功した
  • 各ページ、画像、リンク、スマートフォン表示を確認した
  • 本番移行時に _config.yml を本番用へ戻す予定を確認した
  • 検証終了後のテストサイトの扱いを決めた
